# COMP415 G7: Encrypted Credit Scoring with Homomorphic Encryption

A bank gets a credit score for a loan applicant from an external scoring service
(modelled on KKB / Findeks) without the scorer ever seeing the applicant's data.
Features are encrypted with CKKS (TenSEAL), the scorer runs a logistic regression
on the ciphertext, and only the bank can decrypt the result.

See [PROJECT_PLAN.md](PROJECT_PLAN.md) for the architecture, API contract, scope
and schedule (it wins if anything disagrees). Developer notes are in
[CLAUDE.md](CLAUDE.md).

## Getting started

Needs Python 3.12 (TenSEAL 0.3.18 has a cp312 wheel) and internet access for
`pip` and the one-off dataset download.

```bash
git clone https://github.com/HardtekkX/COMP415-G7.git
cd COMP415-G7
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt

python scripts/setup_demo.py   # once: trains the model, then picks the demo applicants
python -m pytest               # about 25 s; includes an end-to-end run of both services
```

`scripts/setup_demo.py` runs two steps you can also run on their own:

- `python -m training.train` downloads German Credit and writes
  `training/artifacts/` (weights for the scorer, scaler for the bank, metrics,
  and the git-ignored `test_split.csv`).
- `python -m ui.demo_applicants` picks six test applicants, two each for
  approve, review and reject, with made-up national IDs, and writes the
  git-ignored `ui/demo_applicants.json`. Run it again after retraining.

Start the two services, each in its own terminal (with `.venv` activated):

```bash
uvicorn scoring_service.main:app --port 8001   # scorer: holds the weights
uvicorn bank_service.main:app --port 8000      # bank: holds the keys
```

Then, in a third terminal, score one applicant from the test split:

```bash
python -m bank_service.cli --row-id 690
```

It prints the encrypted-path probability next to the plaintext one from
training (difference at most about 3e-7) and the decision. Or call the bank's API
(the national ID is fake; real T.C. numbers never start with 0):

```bash
curl -s localhost:8000/apply -H 'content-type: application/json' -d '{
  "national_id": "00000000001",
  "features": {"duration_months": 24, "credit_amount": 3500, "installment_rate": 3,
               "existing_credits": 1, "checking_status": 1, "savings_band": 0,
               "employment_band": 2, "other_installment_plans": 0, "owns_home": 1,
               "has_guarantor": 0}}'
```

To open the demo screens in a browser, with both services running and the demo
applicants created (`python scripts/setup_demo.py`):

```bash
streamlit run ui/app.py     # UI_BANK_URL / UI_SCORER_URL override the service URLs
```

- **Bank**: pick or edit an applicant, get the decision, and see exactly what
  left the bank (pseudonym, ciphertext size) next to what stayed.
- **Scorer**: everything the scoring service sees and nothing else: recent
  requests (time, pseudonym, context ID, ciphertext size, compute time), the
  SHA-256 fingerprint and a 64-character base64 slice from the middle of a
  selected ciphertext and its encrypted result, and the
  registered public contexts. Needs the scorer's demo endpoints, which are on
  unless it was started with `SCORER_DEMO_ENDPOINTS=false`.
- **Comparison**: the six demo applicants scored through the encrypted path
  next to their plaintext probability from training: the difference, whether
  the decisions match, ciphertext size against plain JSON, and a timing
  breakdown. **Run all six** fills a table.

Good to know:
- The bank's first run creates `bank_service/keys/` (HE secret key, HMAC key).
  It is git-ignored. Delete it to start over with new keys.
- Thresholds (approve below 0.25, reject from 0.50), the scorer URL and the
  keys folder are in `bank_service/config.toml`.
- Training writes `model.json` (weights, scorer only), `preprocessing.json`
  (scaler, bank only) and `metrics.json`, all committed, plus
  `test_split.csv`, which is git-ignored and regenerated by training.

## Status

As of 17 November 2026. Built and tested (169 tests):

| Part | Where | Key numbers |
|---|---|---|
| Model | `training/` | 10 features, test accuracy 0.760 (baseline 0.700), AUC 0.770 |
| CKKS setup | `common/he.py` | N=8192, chain [60, 40, 60], scale 2^40, minimal rotation keys |
| Scoring service | `scoring_service/` | about 6.4 ms median per encrypted score as measured by the running service (about 4 ms in-process); public context 2.9 MB, sent once |
| Bank service + CLI | `bank_service/` | ciphertext 235 KB per request; about 19 ms per applicant inside the bank, 22 ms client round trip (median, one laptop) |
| End to end | `tests/test_e2e.py` | 20 applicants, all decisions agree |
| Evaluation | `evaluation/` | all 300 test rows: 300/300 decisions agree, max probability error 3.9e-7; table in [evaluation/results.md](evaluation/results.md) |
| Demo screens | `ui/` | Bank, Scorer, Comparison (Streamlit, HTTP only); six demo applicants agree on every decision |

The remaining error is not random noise: within one key set the decrypted logit
is off from the exact plaintext logit by almost the same amount on every row
(1.4e-6 above it in the committed run, spread 1.7e-7). The size and sign of that
offset change with each fresh key set (seen from 0.8e-6 to 2.6e-6, either sign).

Security rules covered by tests: the scorer never holds a secret key, the bank
never reads the weights, neither service logs national IDs or feature values.

Still open, per [PROJECT_PLAN.md](PROJECT_PLAN.md):
- Report, slides, two demo rehearsals, backup video.
- Optional: HTTPS between services, Docker Compose, stretch goals.

Limitations and caveats for the report are collected in
[docs/report_notes.md](docs/report_notes.md). One affects the numbers above: the
test split was looked at while choosing the feature encodings, so 0.760 / 0.770
are not from an untouched holdout.

## How we work

- One branch per task (`git switch -c <short-task-name>`), small pull requests
  into `main`.
- Run `python -m pytest` before you push; all tests must pass.
- Never commit keys, certificates or datasets. `.gitignore` covers
  `bank_service/keys/`, `*.key`, `*.pem`, `*.csv` and `training/data/`; check
  `git status` before committing anyway.
